## The question this answers

*"Bring over what that branch has that we don't — especially the Rust AT layer —
and get to their ~10 % CPU / ~100 MB memory."*

Answer, in one line: **the backend half is portable and the transport is now
built; the frontend half is not "their changes" at all — it is fifteen releases of
upstream product evolution, and `AGENTS.md` forbids it on this branch.**

## Intended

Port, in value order: (1) the Rust AT broker, (2) the measured CGI/poller
de-forking series, (3) the handful of correctness fixes that apply to this
firmware. Leave the frontend alone unless something is genuinely required, and
escalate rather than rebase.

## What was measured (2026-10-22, before anything was deployed)

Method — identical on both boxes, `/proc`-only so BusyBox and systemd hosts are
comparable: `utime+stime+cutime+cstime` from `/proc/<pid>/stat` (**including
reaped children** — htop understates a forking shell daemon ~7×), `VmRSS` from
`/proc/<pid>/status`, box busy from `/proc/stat`, and `/proc/stat`'s `processes`
counter for fork rate. 60 s window, idle device, no scan, no live lease.

| Metric | **O5A (this branch) baseline** | X75 (their branch), for scale |
| --- | --- | --- |
| Box busy | **66.16 %** of one core | 41.27 % of total capacity (≈ 82.6 % of one core) |
| `qmanager_poller` | **16.90 %** of one core | 26.82 % |
| `qmanager_ping` | **2.27 %** | 1.23 % |
| `qmanager_atd` | — not installed | **0.10 %** |
| **Fork rate** | **113 /s** | **48 /s** |
| QManager RSS (matched procs) | **3.4 MB** | 2.4 MB |
| Device memory used | **133 MB** of 182 MB `MemTotal` | **106.4 MB** of 231 MB |

**Reading it honestly.** Our fork rate is **2.4× theirs** — that is the transport
cost the broker removes, and it is the metric to watch. But their *per-core*
poller CPU is **higher** than ours, because v0.1.33's poller also runs watchdog,
sites and scenarios. Their "~10 % CPU / ~100 MB" is a **different device with
different features** (QManager's share of a 2-core box was 14.14 % of capacity;
device memory used 106.4 MB). **Matching those two numbers exactly is not a
meaningful goal; closing the fork-rate gap is.**

## What was built

1. **`native/qmanager_atd/`** — the crate vendored from `x75` (16 modules,
   ~7,300 lines) with six O5A deltas, each marked `O5A PORT:` in the source:
   `AT_DEV` env override defaulting to `/dev/at_mdm0`; lock → `/tmp/qmanager_at.lock`;
   pid → `/tmp/qmanager_at.pid`; lock mode 0666; lock budgets 5/10 s → **20/45 s**;
   `BUILTIN_LONG` trimmed back to the three patterns the shell `qcmd` uses;
   restart via `systemctl` instead of procd.
2. **armv7 build** — `armv7-unknown-linux-musleabihf` stanza added to
   `.cargo/config.toml`; `rust-lld` + `crt-static`, no cross gcc. Artifact:
   **513,000 B, ELF 32-bit ARM EABI5, static, stripped, no `INTERP`**,
   version `qmanager_atd 0.2.0 proto=2`.
3. **`deploy/qmanager-atd.service`** — `Before=qmanager-poller.service`,
   `Restart=always`, `ExecStopPost` clears socket + `.proto`, and an explicit
   note that it is **not** enabled by default.
4. **`docs/reference/at-broker.md`** — the built subsystem, O5A-adapted.

## What was deliberately NOT built, and why

- **A frontend rebase.** Measured: the app-layer delta is **622 files, +4,349 net
  lines** (`components/` 369 files, `public/locales/` 60) — and **100 % of it is
  upstream v0.1.19→v0.1.33 product evolution. X75-specific work contributes
  exactly zero app-layer drift** (`git diff 008dedb7 28cb52c4 -- app/ components/
  hooks/ types/ lib/ constants/ public/locales/` → 0 files). A rebase would also
  delete **82 paths that exist only here**, including all three owner-authorised
  exceptions (Detailed Metrics, the neighbour aim strip, the speedtest favourite).
  `AGENTS.md` forbids this and it is not what "their changes" means.
- **Replacing `qcmd` everywhere (spec option A).** The Rust client returns **rc 0
  with `ERROR` in stdout**; this deployment's contract is **rc 1 with empty
  stdout**. ~40 callers test `$?` and would report rejected writes as applied.
- **`qsms`.** It uses the same device as AT; hard rule 3 requires SMS on
  `/dev/smd7` under the vendor radio lock. Not enableable by configuration.
- **`c104c306` (add `cpu-thermal` to the temperature allowlist).** Probed: this
  board has **no `cpu-thermal` zone** at all (42 zones, all `modem-*`, `mdmss-*`,
  `cpuss-*`, `aoss-*`, `pmx65_tz`). It is a ZX7981POEQ fix; porting it would only
  risk changing a value that is currently correct.

## Four firmware probes, run on the O5A (they change what is worth porting)

| Probe | Result | Consequence |
| --- | --- | --- |
| `tr -d '[:space:]'` expands the class | **works** (prints `abc`) | `9ad76d0d`'s 12-site fix is a **no-op** here |
| `stat` applet present | **`/bin/stat`**, `stat -c %Y` works | `fad2da78` + `9cfeee4e` are **no-ops**; this deployment has **no** latent `stat` defect |
| `date -r FILE +%s` | **works** | the `fad2da78` fallback is unnecessary |
| `awk` `x = x (cond) a` | **BROKEN — "Call to undefined function"** | real hazard, but **already documented and avoided twice** in this tree (`phy_metrics.sh:391`, `qmi_read.sh:275`) — **no live defect** |
| `CONFIG_HZ` | **100** (1973 ticks / 20.06 s) | upstream's windowed `cpu_usage` fix assumes **250**; must be re-derived here |
| `stat`-free `/etc/TZ` present | **yes** | the broker's musl local-time path is fine |
| `/var/lock`, `/var/run`, `/run` writable | **all writable** | the lock move to `/tmp` is a *serialisation* requirement, not a filesystem one |

## Still broken / open

1. **Device verification never ran** — smoke test, parity table, socket gate and
   the after-benchmark all need the unit back on the network.
2. **Hard rule 9 is undecided** for the 513 KB binary: commit it (upstream does)
   or fetch it at deploy time (this repo's choice for `jq`/`speedtest`).
3. **No boot hook entry** — correct for now, because the unit is opt-in; it
   becomes mandatory (with a proven reboot) the moment the broker is adopted.
4. **`channel.rs` risk** — one long-lived fd + no retry is unverified on
   `/dev/at_mdm0`; see `at-broker.md` §"Known risk".
5. **The rest of the backend series is unfitted.** Ranked and justified in the
   recon output; the highest-value five, all self-contained and independent of
   the broker:
   - `serve_ndjson_as_array` → sed/tr (`cgi_base.sh:282`) — drops a `jq -s` from
     three polled endpoints; keep this deployment's `_limit` argument.
   - `detect_scc_pci_changes` → one `jq @tsv` (`events.sh:493`) — removes 5+N
     `jq` from the 30 s Tier-2 path; keep this deployment's `_ev_ids` wording.
   - **poller `write_cache` de-forked composer** — a **60-argument `jq -n` every
     2 s** is the largest recurring `jq` cost in the deployment.
   - `qmanager_ping` `write_cache` → `printf` (every 5 s, 13 keys, re-derive).
   - windowed busy-field `cpu_usage` — the current value is *wrong* (single 2 s
     delta, `CONFIG_NO_HZ` denominator); use `CPU_HZ=100` here, not upstream's 250.
